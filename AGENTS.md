# AGENTS.md — QualCoder v4 (rework)

Guidance for AI agents working in this repository.

## Repo layout

- `backend/` — FastAPI + SQLAlchemy (async, SQLite) API. Venv at `backend/.venv`.
  Commands: `backend/.venv/Scripts/python.exe -m pytest tests` (994 tests),
  `-m ruff check src`, `-m mypy src`. Entry: `backend/src/qualcoder_api/main.py`
  (packaged entry `backend/run_packaged.py`; PyInstaller spec `qualcoder_backend.spec`).
- `frontend/` — React 19 + TypeScript + Vite 6 + Tauri 2.
  Commands: `npm test` (vitest, 336 tests), `npx playwright test` (e2e, 53 tests,
  single worker), `npx tsc --noEmit -p tsconfig.json`,
  `npx eslint src --max-warnings 0`.
  Tauri shell: `frontend/src-tauri` (release build via `npx --yes @tauri-apps/cli@2 build`
  from `src-tauri/`; the backend onedir lives in `src-tauri/resources/backend/`,
  copied there by `release.ps1 -Compile`).
- `release.ps1` — unified release pipeline: `release.ps1` (full release),
  `release.ps1 -Compile` (build only), `release.ps1 -ReleaseOnly` (release only).

## Documentation map

- `frontend/src/DESIGN.md` — the authoritative UI spec (layout slots, button
  variants, icon sizes, typography, per-view registry). Every screen must adhere
  to it; the orchestrator is `frontend/src/components/shell/WorkspaceLayout.tsx`;
  views fill slots — they never build their own bars. READ IT FIRST before
  touching any view.
- `frontend/tests-e2e/COVERAGE.md` — the e2e coverage matrix mapping every
  documented user operation to the spec that exercises it (or marks it a gap).
- `frontend/tests-e2e/README.md` — how to run the e2e suite (from `frontend/`).
- `CHANGELOG.md` — version history (Summary on top, consolidated latest release
  at the bottom).
- `backend/src/qualcoder_api/help_docs/*.md` — the in-app Help topics (served by
  `GET /api/v1/help/...` and rendered in the Help pane). `docs/*.md` mirrors them
  for the website and must stay in sync (edit help_docs first, then copy).

## Workflow rules

- Verify before finishing: backend tests+ruff+mypy; frontend
  tsc+eslint+vitest+playwright e2e (start the run from a clean state:
  kill leftover `qcnext`/`qualcoder-backend`/uvicorn/vite/node/python processes
  and delete `%TEMP%\qc-e2e` and `%TEMP%\qc-synctest` if a previous run locked
  them; a stale backend holding port 8765 silently serves the whole suite with
  old code — the backend log then shows a bind error).
- The AI chat can run agentic (MCP tools): the model calls the project's read
  tools (always) and write tools (only at `mcp_permissions` write/full),
  gated by an in-memory single-use approval token (`/api/v1/ai/chat/approve`)
  when `confirm_writes` is on. Writes are audit-logged. Covered by the
  `test_agentic_*` tests in `backend/tests/test_api_ai.py`.
- Do not commit: `frontend/src-tauri/target/`, `frontend/src-tauri/resources/backend/`
  (regenerated by `release.ps1 -Compile`), `tests-e2e/.servers.json`, `tests-e2e/*.log`,
  `updater.key`, `*.qda` user data.
- EXCEPTION (branch `development` only): the compiled artifacts ARE committed there on
  request of the repo owner — backend onedir + release exe as regular git files,
  MSI/NSIS installers via git-lfs (`git lfs track "*.msi" "*-setup.exe"`, then
  `git add -f`). Keep artifacts off all other branches.
- RELEASE NOTE (repo owner): upload the generated artifacts to GitHub releases —
  the portable `qcnext.exe`, the NSIS setup .exe + its .sig, and the update
  manifest (`qcnext-latest.json`) — NEVER the .msi. GitHub CI builds MUST NOT
  require the signing key: the release workflow degrades to unsigned builds when
  `TAURI_SIGNING_PRIVATE_KEY` is absent (tauri fails with "A public key has been
  found, but no private key" otherwise).
- LINUX: build only the flatpak bundle for now (`tauri build --bundles flatpak`);
  no deb/rpm/appimage.
- Never edit user data under `~/.qualcoder/` except to restore the settings
  file after test runs (e2e wipes it; restore recent project + sync off).
- The user's real project for manual verification:
  `D:\Downloads\LSTeach2.0_BKUP_20260714_21.qda` (contains category/code id
  collisions — tree code must stay namespace-aware with a depth cap).
